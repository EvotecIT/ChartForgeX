# ChartForgeX 1.0 Migration

ChartForgeX 1.0 removes pre-release duplicate construction and styling surfaces. The migration is intentionally breaking: there is one public model for each reusable concept, and hosts keep product-specific data outside the renderer.

## Construction and data

`ChartForgeX.Simple` and its deferred chart definitions have been removed. Build native `Chart` objects directly, or map host records with `ChartDataset<T>` and the typed `AddLine`, `AddBar`, `AddArea`, `AddScatter`, and `AddHistogram` overloads.

```csharp
using ChartForgeX.Core;
using ChartForgeX.Data;

var rows = ChartDataset<Sample>.From(sourceRows)
    .Filter(row => row.Enabled)
    .SortBy(row => row.Timestamp);

var chart = Chart.Create()
    .AddLine("Latency", rows, row => row.Timestamp.ToOADate(), row => row.LatencyMs)
    .WithXAxisScale(ChartScaleKind.Time)
    .WithYAxisScale(ChartScaleKind.Logarithmic);
```

Use `ChartGrid.FromFacets(...)` for deterministic small multiples. Product DTOs, data collection, filters, and dashboard shells remain in the host.

## Consolidated types

| Before 1.0 | 1.0 surface |
| --- | --- |
| `ChartTextStyle` | `TextStyleOverride` for optional chart-role overrides; `TextStyle` for a complete resolved style |
| `VisualTextAlignment`, `VisualCanvasTextAlignment` | `TextAlignment` |
| `ChartGridPanelFit`, `VisualGridPanelFit` | `VisualPanelFit` |
| `VisualArtifactRect` | `ChartRect` |
| `TopologyDirection`, `FlowArtifactConnectorDirection`, `WardleyMapFlow` | `VisualLinkDirection` |
| `System.Drawing.Color`, `PointF`, `RectangleF` in consuming hosts | `ChartColor`, `ChartPoint`, `ChartRect` |

No compatibility aliases are provided. This keeps old names from becoming a second public API that must be maintained after 1.0.

Parser diagnostics now share `ChartForgeX.Diagnostics.VisualDiagnosticSeverity`; replace `MarkupDiagnosticSeverity` and `MermaidDiagnosticSeverity` with that type. Mermaid sequence participants now use `SequenceArtifactParticipantKind` directly instead of the duplicate `MermaidSequenceParticipantKind`.

## Axes and scales

`ChartAxis` is the source of truth for explicit or automatic bounds, tick count, label density, label angle, visibility, formatting, and scale selection. Configure it through `ConfigureXAxis`, `ConfigureYAxis`, or `ConfigureSecondaryYAxis`.

Supported scale kinds are `Linear`, `Logarithmic`, `SymmetricLogarithmic`, and `Time`. SVG and PNG use the same scale transform and tick model. Logarithmic axes reject non-positive bounds and data instead of producing invalid output.

The pre-1.0 `Category` and `Band` enum values were removed because the renderers never implemented discrete-axis semantics for them. Use explicit axis labels with a `Linear` scale for numeric category positions.

## Typography

`FontSpec`, `TextStyle`, `TextStyleOverride`, `TextAlignment`, and `TextLayoutEngine` form the shared dependency-free typography contract. `TextDecorationStyle` adds single, double, dotted, dashed, and wavy underline or strikethrough patterns; `TextBaseline` adds subscript and superscript; and `TextCaseTransform` adds upper, lower, title, sentence, and toggle-case display transforms. Charts, topology, visual blocks, visual canvas, and `ImageComposition` resolve text through this layer. SVG, HTML, and dependency-free raster output share these semantics, while raster output can select TrueType files or collections without relying on `System.Drawing`.

## Design and accessibility

`VisualDesignTokens` applies product-neutral colors, typography, radii, and stroke width across `ChartTheme`, `VisualCanvasTheme`, and `TopologyTheme`. Hosts can use one token set for charts, topology diagrams, reports, and wallpaper composition.

Charts, topology, and visual canvases expose `VisualAccessibility` through `ConfigureAccessibility(...)` and `AsDecorative()`. Capable SVG renderers emit a title, description, language, role, and ARIA metadata; decorative visuals are hidden from assistive technology.

## Graphite default look

`Chart.Create()` and visual blocks now use `ChartTheme.GraphiteLight()`. Choose `GraphiteDark()` for a dark surface, or apply `VisualDesignTokens.GraphiteLight()` / `GraphiteDark()` when a host shares tokens across outputs. All public additions are optional; existing chart construction remains valid.

The new defaults change rendered output:

- Flat bars have a 2 px radius at the value end and a square baseline. Areas use a flat 12% fill for one series; multiple area series retain their lines without overlapping fills. Other Graphite families omit gradients, highlights, gloss and inner shadows.
- Each chart has one surface. `.WithHostFrame()` omits it and removes outer padding. Grids use a flat page, 16 px gaps and 15 px panel titles.
- Titles are 17 px at weight 700; subtitles are 13.5 px muted. The plot has horizontal guides and a zero baseline, with no y-axis line or tick marks by default. Requested y-axis titles are horizontal.
- Legends are inline below the subtitle and hidden for one series. Lines are straight and 2 px wide, with the final marker visible; use `.WithLineMarkers(ChartLineMarkerMode.All)` to draw every marker.
- Donuts use a 62% hole, sort from largest to smallest, and combine smaller slices into **Other** when more than six slices are present. `ChartOptions.MaximumPieSlices` changes that limit. Their legend lists the name, value and percentage beside the plot, or underneath a narrow plot.
- Gauges use a 240° arc with butt ends. `.ConfigureGauge(...)` sets bands, a target, caption and needle form; `.AddLinearGauge(...)` adds a bullet-style linear gauge. Bullets use neutral rectangular bands and a thin text-coloured measure. These families have no series legend.
- Compact labels preserve full numeric values in accessible names and SVG data attributes. Sankey links are flat source colours at 35%; heatmaps use discrete sequential steps, neutral zeros and a compact ramp legend.
- Labels respect an active plot clip. Dense panels hide a value when no readable position fits and retain it in the mark's accessible name. Fitted inside-bar labels use contrasting ink; explicit custom label colours remain in place. PNG keeps literal theme colours when SVG custom properties are enabled.

Series colour semantics are additive: `.WithSeriesState("Failed", ChartSeriesState.Danger)` declares a state without relying on the display name. `Quiet` and `Success` use the quiet line colour for line series and draw underneath other states. Explicit series colours still take precedence.

To retain the earlier surface and mark effects, choose a named theme such as `ChartTheme.Light()`, `Dark()`, `ReportLight()`, `ReportDark()`, `Aurora()` or `Candy()`. Bar effects remain available through `ChartBarStyle.Solid` and `SegmentedCapsule`; flat bars use `Flat`. Explicit axis, legend and typography options remain supported.

`ToSvgColorVariables()` adds Graphite guide, state, neutral and contrasting ink properties. Hosts that supply their own property names should map the new `.ink` paths together with their fills. `SvgColorVariables.AddInk(...)` pairs a custom fill with its readable text property. A custom series colour stays literal unless the host maps it.

Generated token JSON can opt into Graphite with a `graphite` object in each mode. It contains the colour roles `muted`, `grid`, `axis`, `info`, `quiet`, `quietLine`, `neutral`, `neutral2` and `neutral3`; the existing `surface`, `text`, `series`, severity and ramp fields remain the source for their respective colours.

The [design specification](design/chart-look-spec.html) defines the approved light and dark appearance.

## Dense legends

Long series, point, pie, and progress-ring legends now use a height budget and an explicit overflow count. This changes legend visibility without removing plotted data. Use `WithLegendBudget(maximumHeightFraction: 0.5, maximumRows: 8)` when a report needs more legend space, or split the data into smaller charts. A budget too small for one readable row omits the legend to protect the plot. Hosts that inspect SVG can read visible summaries through `data-cfx-role="legend-overflow"` and `data-cfx-omitted`; do not assume every source series has a visible legend item.

## Responsive composition

`VisualCanvas.WithResponsiveLayout(designWidth, designHeight, fit)` separates layer coordinates from output dimensions. `Contain`, `Cover`, and `Stretch` use the same design-space contract in SVG and PNG, so a host can reuse one composition for multiple wallpaper, report-cover, or social-image sizes.

## Topology mapping

`TopologyChart.FromData<TNode, TEdge>(...)` maps product-owned node and edge records into the product-neutral topology model. The mapper preserves input order and rejects duplicate node ids, duplicate edge ids, and dangling endpoints before rendering.

## Raster input and dependencies

The core ChartForgeX package has no runtime package dependencies. Its raster input supports PNG, GIF, JPEG, BMP, PPM, and uncompressed RGB TIFF through dependency-free readers. GIF input uses the first frame; animated GIF and APNG output remain separate deterministic export paths.

ImagePlayground now consumes native ChartForgeX charts instead of maintaining its own chart command DTOs and renderer choices. PowerBGInfo uses ChartForgeX colors, geometry, typography, composition, and raster input instead of `System.Drawing`.

## Changes after 1.8.1: reporting additions

These notes cover the release after 1.8.1 that ships the reporting additions (time axes, state timelines, categorical and hour-by-weekday heatmaps, Gantt lanes, design-token intake, shared bundle assets, and dense topology layout). Most of them are new APIs; the items below change existing output or contracts. Summarise them in the GitHub Release notes for that version.

### Time axes and dates

- `ChartScaleKind.Time` axes place calendar-aligned ticks (seconds through years, chosen from the range and `TickCount`) instead of numeric ticks on OLE dates. Labels read `yyyy-MM-dd` at midnight and `HH:mm` (or `HH:mm:ss`) otherwise; previously every tick was `yyyy-MM-dd`. Explicit labels and `LabelFormatter` still win. Ranges shorter than one second, before 1899-12-30, or outside the OLE date range fall back to numeric ticks.
- Time-axis values are UTC instants, shown in UTC unless `ChartAxis.TimeZone` is set. `ShowTimeZone` appends the zone designator (`UTC`, the zone id, or `TimeZoneLabel`) to the x-axis title, or uses it as the title when none is set.
- `ChartPoint(DateTime)`, `ChartAxisLabel(DateTime)`, `WithXDateLabels`, and the `ChartRangeBand`, `ChartInterval`, `ChartDumbbell`, `ChartErrorBar`, `ChartBubble`, `ChartBoxPlot`, and `ChartCandlestick` date constructors convert `DateTimeKind.Local` to UTC and treat `Unspecified` as UTC. Charts that passed `DateTime.Now` and formatted labels themselves now receive UTC instants; pass `DateTime.UtcNow` or set `ChartAxis.TimeZone` for local wall-clock labels. Daily series built from `DateTime.Today` or Local `.Date` values move off midnight by the UTC offset; use `DateTime.SpecifyKind(date, DateTimeKind.Unspecified)` or UTC dates. Raw `ToOADate()` values are not converted, so do not mix them with `DateTime` labels built from Local dates. Date-based charts (calendar heatmaps, the classic timeline and Gantt, `WithGanttToday`) keep wall-clock dates unchanged.

### Heatmaps

- Sequential heatmaps and hexbins (the default scale) keep their colours, but cells and scale steps expose `data-cfx-level` (0–4) instead of `data-cfx-status="positive|warning|negative"`. Only `ChartHeatmapScale.Semantic` still emits statuses; combining it with the new `HeatmapRelativeScale` throws `InvalidOperationException`.
- Calendar heatmap cells and scale steps no longer carry `data-cfx-status` (they already exposed `data-cfx-level`); empty cells keep `data-cfx-status="empty"`. The default high colour is the first categorical palette colour instead of `ChartTheme.Positive`; set a series colour to keep the previous look.
- Interactive HTML tooltips for these cells show a `Level` row instead of `Status`.
- A zero in a count heatmap (`HeatmapRelativeScale`, which hour-by-weekday heatmaps set) or a calendar is drawn in a neutral colour instead of the weakest ramp step, and keeps `data-cfx-level="0"`. In a calendar with zeros the ramp starts at the smallest non-zero value (its level is at least 1) and the scale gains a `calendar-heatmap-scale-zero` swatch, so the first `calendar-heatmap-scale-step` now carries that value instead of 0. A colour set on the day itself still wins.
- Calendar weekday labels are drawn on every row when the cells are tall enough, otherwise on Monday, Wednesday, and Friday wherever the week starts. The month of the first value is named even when the window starts mid-month, unless the next month begins before that label would end. Scale-step levels now equal the level of a cell with that value, so the first step is level 1 in calendars (a non-zero value is never level 0). `AddCalendarHeatmap` gained optional parameters, so code compiled against an earlier build must be recompiled. Cells expose `data-cfx-row` (the row from the first day of the week); `data-cfx-weekday-index` stays the `DayOfWeek` number.
- A calendar heatmap with the default padding lays itself out over the chart area (below the header text when a header is drawn, inside the card when a card is drawn, 8 px from the edge) instead of inside the cartesian padding, which left a 230 px card with 1 px days. Its cells are larger unless `WithCalendarHeatmapCells` limits them. Padding set with `WithPadding`, `ChartOptions.Padding`, or a builder that sets it keeps the previous layout. The header draws its title and subtitle at the same baselines as before. Day cells are named through `ChartLabels.DateFormatter` (default ISO, as before).
- Static SVG heatmap, calendar, hexbin, dotted map, region map, and tile map marks no longer carry `tabindex="0"` and `focusable="true"`: every mark used to be a tab stop. They keep `role="img"`, `aria-label`, and the `cfx-interactive-region` class; the interactive HTML adapter still makes them focusable at runtime. Hosts that relied on focusing static cells must use the interactive adapter.
- Calendar heatmap descriptions count a day at zero (drawn neutral, a day without changes) apart from the days with a value. In `ChartDescriptionFacts` for `CalendarHeatmap` and `CalendarHeatmapGroup`, `Count` is the number of days with a non-zero value (was every dated value, zeros included, for the chart description and every day with data for the group), the new `ZeroCount` is the number of days at zero, and `MissingCount` is the number of days without data (for `CalendarHeatmap`, between the earliest and the latest value; was always 0). A host sentence that said "days with a value" from `Count` stays right; one that meant every day in the data uses `Count + ZeroCount`. The English text changes from "with 5 dated values." and "with 5 filled days and 72 empty days" to, for example, "with 4 days with a value, 1 day at zero, and 71 days without data." (parts with a zero count are left out). `ChartDescriptionFacts` gained the optional constructor argument `zeroCount`, so code compiled against a preview build must be recompiled. The `data-cfx-filled-day-count` and `data-cfx-empty-day-count` attributes are unchanged.
- Design tokens with `ramps.sequential` replace the neutral ramp through `WithDesignTokens` for cells without a series or point colour.
- Text on filled marks (matrix and hexbin heatmap values, categorical heatmap cell text, Gantt lane item labels) takes the theme text colour or the surface behind the marks (`ChartOptions.MarkBackdrop`) instead of a literal `#FFFFFF` or `#0F172A`, chosen by where the cell sits on its scale instead of by its colour: the surface on solid state marks, semantic cells, cells from 35 % of a sequential ramp, and series tints of 90 % or more; the text colour on quiet and outlined marks, neutral zeros, and weaker cells. When that colour reaches less than 3:1 on the mark and the other contrasts more, the other is used. Cells where the previous luminance rule and the scale position disagree change text colour (on light themes, for example, cells between the second and third sequential steps and strong series tints below 90 % now take the dark text colour), white text is the surface behind the marks (still white on white surfaces), and dark text on dark themes is that surface instead of `#0F172A`. With SVG colour variables this text is written as the surface and text properties, so a heatmap with cell numbers or Gantt lanes with labels can be one SVG for both themes when every strong fill reaches 3:1 on the surface behind the marks in both themes (the Graphite tokens on `ChartMarkBackdrop.Card` do).

### Maps

- `ChartColorScale` holds any number of colour stops: `Sequential(colors)` spreads them evenly, and `Diverging(lowColors, midpointColor, highColors, midpointValue)` spreads each arm between the minimum or maximum and the midpoint. `Colors` lists every stop. The two- and three-colour factories draw as before.
- `VisualDivergingRamp.ToColorScale` and `VisualDesignTokens.ToSequentialColorScale` keep every ramp colour instead of blending between the end colours, so intermediate values take the token steps. `LowColor`, `MidpointColor`, and `HighColor` are unchanged.
- A horizontal map scale with more than three stops draws one swatch per stop (up to 11; longer ramps are sampled), each at the value where its stop is exact, and puts the midpoint label under the midpoint stop; when the midpoint sits at the minimum or maximum the swatches are spaced evenly and the label goes under that end. Two- and three-colour scales keep five swatches.

### Topology

- `TopologyRenderOptions.ReadableDenseLayout` is off by default, so existing charts render as before. When enabled, `DenseGrouped` wraps site panels into rows (left-to-right or right-to-left with more than six groups), keeps `Auto` groups of 10–24 nodes as card grids, and reserves caption space; obstacle-avoiding edges without waypoints treat tile captions as part of the card in any layout.
- With `ReadableDenseLayout`, obstacle-avoiding edges without waypoints are now routed together (see `docs/topology.md`), so their routes, attachment sides, and edge-label positions differ from the previous per-edge corridor choice; `data-route-corridor` is `maze` for every planned route and `data-route-candidate-count` is 1. Anonymous port fanning no longer applies to these edges because lane separation spreads the ends. Card rows in `Grid` and `PairRows` groups can sit up to 30 px further apart when many routed edges end in the group. Charts without the option are routed as before.
- A legend edge entry without a line style (`AddEdgeKind(label, kind)`) was always drawn dashed. It is now solid unless every edge of that kind in the chart is dashed or dotted. Pass `lineStyle:` to fix the sample.
- With `ReadableDenseLayout`, tile captions wrap to `MaxNodeLabelLines` (two by default) before they are shortened, so captions that used to end in an ellipsis can take a second line and the rows of their group sit further apart.
- `TopologyRenderOptions.IdScope` and `ToSvg(this TopologyChart, string idScope, TopologyRenderOptions? options = null)` scope every SVG id of a topology render. Because of the new overload, `topology.ToSvg(null)` no longer compiles (the call is ambiguous); call `topology.ToSvg()` instead. A topology whose `Id` is white space now references its shadow filter as `topology-shadow`, the id the filter is defined with (the reference used to point at a missing id).
- SVG arrow and endpoint markers of a topology are named after where the edge colour comes from instead of the colour: `{root}-arrow-{key}` and `{root}-circle-{key}` / `{root}-diamond-{key}`, where the key is the status (`healthy`, `warning`, `critical`, `disabled`, `unknown`), `muted`, or `color-N` for the N-th distinct explicit edge colour in edge order (was the colour, for example `{root}-arrow-dc2626`). Light and dark renders of one chart now reference the same markers, so with SVG colour variables a topology with arrows can be one SVG for both themes. Every status marker is defined even when two statuses share a colour. Hosts that selected markers by the colour in their id must use the key. Two renders in one document that share a root id (the same chart `Id`, or none) and no `IdScope` could share colour-keyed markers safely; their keyed markers can now differ in colour, so give each render its own `IdScope` (light and dark drawings of one chart included).
- With `ReadableDenseLayout`, `DenseGrouped` site panels that fit in one row or grid (left-to-right and right-to-left layouts with up to six groups, and the other directions) take the height of their content instead of sharing out the viewport height, panels in one row of the grid share one height, and bottom-to-top layouts flip the panels within their content instead of the viewport. For every readable `DenseGrouped` chart, wrapped rows included, the prepared viewport height, which is the SVG and PNG canvas height, is fitted to the content plus the legend, so it can be smaller than the requested height (it used to only grow). Small topologies (for example two sites with one row of cards each) no longer draw panels several times taller than their cards with the legend far below. `VisualArtifact.NaturalSize` of a topology still reports the requested viewport. Hosts that relied on a fixed canvas height set `FitContentToViewport` or size the container from the rendered height. Charts without the option are unchanged.
- `TopologyLayoutDiagnosticReport.Groups` is a `List<TopologyLayoutGroupDiagnostic>` (was `List<TopologyLayoutBoundsDiagnostic>`), so each group also reports its `HeaderBounds`. `Id` and `Bounds` are unchanged; code that declared the list or its items with the base type needs the new type or `var`.

### JSON input limits

- GeoJSON map and topology icon-pack JSON cap nesting at 64 levels; deeper input throws `ArgumentException` instead of exhausting the thread stack. Interchange documents keep their 32-level limit, and the new design-token reader allows 32.

### Options

- `SvgColorVariables`, `ChartOptions.SvgColorVariables` (`Chart.WithSvgColorVariables`), `ChartGrid.SvgColorVariables`, `TopologyRenderOptions.SvgColorVariables`, and `VisualDesignTokens.ToSvgColorVariables` let SVG output write token colours as CSS custom properties with literal fallbacks. The default is off, so SVG output does not change unless it is set; PNG output never changes.
- Colour variables have roles. Preview builds took `SvgColorVariables.Add(name, color, appliesToText: false)` and exposed `SvgColorVariable.AppliesToText`; now `Add(name, color, SvgColorRole role = Any)` and `SvgColorVariable.Role`, where `SvgColorRole.Surface` is what `appliesToText: false` was. `ToSvgColorVariables` assigns the role of each token path. With variables set on a chart, grid, or topology, derived colours (line sheen, surface highlights, topology contrast white) stay literal instead of taking a token whose colour they happen to equal, blends of token colours are written as `color-mix(in srgb, …)` of their properties, and role-typed colours prefer the variable of their role. `SvgColorVariables.Apply(svg)` on finished markup still matches by value only, so hosts that want these roles set the variables on the chart instead of applying them afterwards. With variables, a bar's `data-cfx-color` carries the same CSS paint as its fill.
- A calendar day without data is the surface behind the cells blended 30 % towards the muted text colour on every theme. Dark themes used a separate rule (the plot background towards the grid colour), so empty days on dark themes are lighter than before; on light themes the colour changes only where the plot background is not drawn.
- `ChartOptions.PinStateColorsInForcedColors` (`WithStateColorsPinnedInForcedColors`) and `TopologyRenderOptions.PinStateColorsInForcedColors` (`TopologyRenderOptions.WithStateColorsPinnedInForcedColors`) are new and off by default. Topology status legend line and dot swatches and node detail status dots now carry `data-cfx-status`; with the pin, a topology writes its `<style>` element even when `IncludeCss` is off.
- `ChartOptions.Labels` and `Chart.ConfigureLabels(...)` hold some of the words ChartForgeX writes on its own, currently `Now`, `ongoing`, `so far`, `Hour of day`, and the interactive tooltip `Level` row. Defaults are unchanged; set them to localize. The calendar and map scale words `Less`, `More`, and `No data` are covered too (`ChartLabels.Less`, `More`, `NoData`). So is the automatic accessible text: `UntitledChart` (default `ChartForgeX chart`) and `AccessibleTextFormatter`, which receives `ChartDescriptionFacts` and writes the SVG `desc` and the accessible names of calendar and map groups; the English defaults are unchanged. `HtmlChartRenderer.RenderPage` writes `Accessibility.Language` as the page `lang` when it is set (was always `en`). Topology diagrams have the same through `TopologyChart.Labels` (`ConfigureLabels`): `UntitledTopology` (default `ChartForgeX topology`), `UntitledReport` (default `Topology report`, the title of a report from an untitled diagram), and `AccessibleTextFormatter`, which receives `ChartDescriptionFacts` of the new kind `ChartDescriptionKind.Topology` (`Count` nodes, new `GroupCount` and `EdgeCount`); the English description is unchanged. The static topology HTML page writes `Accessibility.Language` as the page `lang` (was always `en`); the interactive page keeps `en` because its controls are English. `ChartDescriptionFacts` gained the optional constructor arguments `groupCount` and `edgeCount`, so code compiled against a preview build must be recompiled.
- Interactive pages can reference shared runtime files instead of inlining them through `ExternalAssets` on `HtmlChartInteractionOptions`, `HtmlInteractiveDashboardOptions`, and `HtmlGraphExplorerOptions`, and through `HtmlInteractiveTopologyRenderer.RenderPage(chart, options, assets)`. Inline remains the default; fragments are unaffected.
- `ChartBarStyle.Flat` (`ChartBarVisualStyle.Flat()`) fills bars, horizontal bars, histograms, range bars, and waterfall steps with their colour only. `Solid`, the default, still draws the derived gradient and the top highlight; only its documentation changed, which described it as flat.
- `ChartStateCategory` takes a pattern instead of a flag. Before: `new ChartStateCategory(key, label, color, hatched: true)` and `category.Hatched`. After: `new ChartStateCategory(key, label, color, ChartStatePattern.Hatched)` and `category.Pattern`. The other patterns are `Solid` (default), `CrossHatched`, and `Outlined`; the optional fifth argument `emphasis: ChartStateEmphasis.Quiet` lightens the expected state.
- `VisualStatusTokens.OperationalStateCategories()` now draws `unknown` with a dashed outline (`ChartStatePattern.Outlined`; was hatched, the same as `notObservable`, and cross-hatched in later preview builds), as the token metadata (`state.unknown: dashedOutline`) and report views draw it, and `OutcomeCategories()` draws `couldNotEvaluate` outlined (was a solid neutral fill). Hosts that want the cross-hatch back pass their own category with `ChartStatePattern.CrossHatched`, which is unchanged.
- The outline of an `Outlined` state mark is dashed (3 px dashes and 2 px gaps, `stroke-dasharray="3 2"` in SVG), as report views dash that state; preview builds drew it solid. As in SVG, a PNG mark 1.5 px or less wide or tall no longer gets an outline.
- Hatch lines take the colour behind the marks instead of literal white, so they differ on themes whose surface is not white. `ChartOptions.MarkBackdrop` (`WithMarkBackdrop`) chooses that colour; the default `Layered` is the theme background (drawn or not; with `TransparentBackground` it stands for the surface the host places the chart on) with the card and the plot background composited over it where they are drawn. A card is now only composited when it is drawn (`ShowCard` and the theme's `UseCard`), so the `Bare` surface style no longer takes its undrawn card colour. `Background`, `Card`, and `Plot` take one theme surface whether or not it is drawn; a host that sets `ChartTheme.Background` to its card colour on a transparent chart can use `Card` instead.
- A `ChartHeatmapCell.Tooltip` no longer replaces the accessible name or the hover text of the cell. The `aria-label` and the hover `<title>` are both `row, column: state. tooltip` (the `<title>` used to be the tooltip alone), as the interactive HTML adapter already showed. Hosts that repeated the row, column, and state in every tooltip can drop them.
- Matrix and categorical heatmap column labels follow `XAxisLabelAngle`: with an angle they rotate at the tick font size (shortened at 120 px, with the plot moved in on the side they slant towards, and thinned to every n-th column when neighbours would overlap) instead of shrinking and being cut off, and the numeric heatmap scale moves below them. The SVG plot of a matrix heatmap no longer also reserves the generic x-axis band, which only mattered with an angle or a small bottom padding.
- `AddHeatmapCategoryRow` accepts a row whose cells are all null (it used to throw `ArgumentException`), and a categorical heatmap may consist only of such rows. The overloads taking `IEnumerable` gained an optional `group` argument, so a call that passes two bare `null` arguments after the name is now ambiguous; pass a typed array.
- `AddStateTimelineLane` gained an optional fourth argument `group`.
- The lane summary header of state timelines and Gantt lanes is drawn inside the plot frame: the lanes start 3 px lower when a header is set, and the header baseline sits 5 px above them (was 8 px). The Gantt "Now" label uses the same baseline, and its lanes start 1 px lower.
- `AddStateTimelineLane` takes `(name, segments, summary, group)` while `AddGanttLane` takes `(name, items, group, summary)`; the state timeline keeps its existing third argument, so name the arguments when passing both.
- Preview builds of the reporting stack named the lane summary header `StateTimelineSummaryHeader`; the shipped name is `ChartOptions.LaneSummaryHeader`, shared by state timelines and Gantt lanes.
