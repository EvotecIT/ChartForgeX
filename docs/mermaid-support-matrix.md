# Mermaid Support Matrix

This matrix is the working contract for ChartForgeX Mermaid support. A family is complete only when it has source-preserving parsing, typed semantic models where rendering is implemented, diagnostics for unsupported syntax, deterministic SVG and PNG output where renderable, Markdown fence coverage, Mermaid.js conformance fixtures, and smoke tests that prove the public artifact contract.

The current compatibility reference is **Mermaid.js 12.1.0**, pinned by [the test-time harness](../tests/mermaid-conformance/package.json). This inventory was checked against `main` at `09065c59` and upstream 12.1.0 documentation on 10 October 2026. Open candidates are listed separately below; their APIs and proof must be rechecked after merge.

## What support means

- **Native render path:** the parser produces a typed model and can create a CFX artifact for a supported subset.
- **Retained only:** source or metadata survives, but a requested feature does not affect visible output.
- **Approximate mapping:** meaning is projected into a CFX chart/topology model with documented fidelity limits.
- **Diagnostic-only family:** the header is recognized and source is retained, but no artifact is produced.
- **Unknown family:** the header is not recognized and parsing returns an error.

Thirty families have native render paths, ZenUML is diagnostic-only, and Agentflow and Railroad are unrecognized. Each native row still has open grammar, configuration or fidelity work; none of these counts establishes complete Mermaid compatibility. Existing smoke/artifact tests are evidence for their tested cases, not a claim that every upstream example passes.

## Recognized But Not Renderable Yet

These families are detected and returned as `MermaidDocument` with raw body statements in `RawStatements`, plus a warning diagnostic. They should not emit a visual artifact until a semantic model and deliberate ChartForgeX mapping exist.

| Family | Header | Current state | Best next target | Notes |

| ZenUML | `zenuml` | Recognized, raw statements retained, warning diagnostic | Sequence-like artifact after grammar evaluation | Keep separate from Mermaid sequence until semantic differences are understood. |

## Missing Upstream Families

The Mermaid 12.1.0 source registers both families below. They are absent from the CFX header dispatcher, rather than recognized diagnostic-only families.

| Family | Headers | Current CFX state | Implementation target |
| --- | --- | --- | --- |
| [Agentflow](https://mermaid.js.org/syntax/agentflow.html) | `agentflow-beta` | Unknown-family error; no typed model or conformance fixture | Typed nested flows/global scope, collapsed containers, metadata, connectors and sequence/reference/failure edges over reusable topology scenes. Treat instructions/models/connectors as inert diagram data. |
| [Railroad](https://github.com/mermaid-js/mermaid/blob/mermaid%4012.1.0/packages/mermaid/src/docs/syntax/railroad.md) | `railroad-beta`, `railroad-ebnf-beta`, `railroad-abnf-beta`, `railroad-peg-beta` | Unknown-family errors; no typed grammar model or renderer | One product-neutral grammar-diagram model and native scene renderer, with separate notation parsers and bounded rule-reference/repetition layout. |

Start with recognition and preserved-source diagnostics, then complete the semantic and artifact gates. ZenUML remains a separate grammar/license evaluation; translating it as ordinary Mermaid sequence syntax would discard meaning.

## Cross-Family Gaps

| Contract | Confirmed current state | Required completion |
| --- | --- | --- |
| Version coverage | One upstream version, 12.1.0, is installed by the harness. Legacy header aliases exist, but there are no separate Mermaid 10/11 reference lanes. | Select exact historical references, retain supported old spellings, annotate fixture applicability and publish only the qualified syntax window. Test-only JavaScript versions do not become runtime dependencies. |
| Conformance depth | 42 `.mmd` sources. The upstream harness parses all and compares selected flowchart nodes/edges and Gantt task dates with four expectation files; it does not render reference images. | Extend feature and semantic coverage on both sides; record source version/provenance and meaningful rejection cases. Add observed render comparisons separately. |
| Result fidelity | Parse warnings and retained statements exist; render results carry parser diagnostics. Some accepted source features only appear in AST/artifact metadata. | Classify unsupported/retained/approximate features consistently, with stable diagnostic identities and original spans; stop unsupported syntax becoming ordinary nodes or labels. |
| Configuration and themes | Presentation parsing interprets a scalar theme. `dark`/`default` select static palettes for several model types; other keys are generally warned/retained. Sequence themes are retained without application. | Typed supported front matter and legacy init declarations, explicit host/source precedence, shared theme-variable/family-option mapping and diagnostics for every unmapped setting. |
| Mermaid 12 appearance | CFX uses its own deterministic prepared scene. It does not execute upstream ELK or reproduce the new default browser appearance. | Describe syntax/semantic compatibility separately from `layout`, `look`, theme and pixel fidelity. Handle legacy `defaultRenderer` and upstream layout aliases deliberately. |
| Labels and authored styling | Several parsers retain Markdown/icon/style data; visible application differs by family. Flowchart metadata shape aliases cover a subset of the upstream catalog. | Shared safe rich-text, shape and style mappings; explicit HTML/math/icon fallbacks, source-order/default-class semantics and SVG/PNG geometry proof. |
| Graph layout and notation | Shared topology provides native markers, groups and routing, but family-specific configuration and composite behavior remain incomplete. | Qualify nesting, local directions, group endpoints, ports, loops, parallel edges, obstacle/label routing and the actual class/state/ER/architecture notation. |
| Host policy and safety | Static output is script-free by default and existing topology/artwork safety contracts are reusable. `MermaidRenderOptions` is a per-family option container, without a Mermaid-wide family/style/resource policy. | Coherent diagram/style/link/asset policy and bounded source/model/output limits over existing safety owners; malformed/adversarial source and embedded SVG proof. This is a qualification gap, not a reported exploit. |
| Delivery | Native artifact, fence, serialization and AOT tests exist, and the quality workflow covers Windows/Linux/macOS. This audit inspects source; it does not rerun those gates or verify published packages. | Qualify each completed tranche through direct APIs, fences, serialization, actual SVG/PNG views, representative hosts, supported frameworks/AOT and isolated package consumers. Verify publication separately. |

The source evidence is [header dispatch and parse results](../ChartForgeX.Mermaid/MermaidParser.cs), [presentation parsing](../ChartForgeX.Mermaid/MermaidParser.Presentation.cs), [presentation application](../ChartForgeX.Mermaid/MermaidPresentation.cs), [render options](../ChartForgeX.Mermaid/MermaidRenderOptions.cs), [Gantt duration parsing](../ChartForgeX.Mermaid/MermaidGanttParser.cs), and [the upstream harness](../tests/mermaid-conformance/validate-mermaid.mjs). ## Completion Order

The implementation checklist lives in [TODO.md](../TODO.md#mermaid):

1. Establish versioned feature/semantic evidence and truthful diagnostics, including missing-family recognition.
2. Complete shared configuration, labels, styling, policy and layout owners.
3. Close core flowchart/sequence/class/state/ER/requirement semantics.
4. Qualify chart/calendar fidelity using existing owner candidates.
5. Complete specialized diagrams and implement missing language families against the same shared owners.
6. Qualify host delivery, visible exports, frameworks/AOT and package consumers; settle merge/release gates separately.

A family closes only when its documented syntax, semantics, diagnostics, visible scene, SVG/PNG exports and fence/consumer contracts pass. Retaining raw text or accepting one fixture is insufficient.
