# Mermaid Support Matrix

This matrix is the working contract for ChartForgeX Mermaid support. A family is complete only when it has source-preserving parsing, typed semantic models where rendering is implemented, diagnostics for unsupported syntax, deterministic SVG and PNG output where renderable, Markdown fence coverage, Mermaid.js conformance fixtures, and smoke tests that prove the public artifact contract.

The current semantic reference is **Mermaid.js 12.2.0**. The [test-time harness](../tests/mermaid-conformance/package.json) also pins 10.9.8 and 11.17.2; [per-fixture compatibility metadata](../tests/mermaid-conformance/compatibility.json) records syntax outcomes and explicit older semantic differences. These tested examples do not establish full compatibility with every release or syntax form in those majors. The family inventory follows upstream 12.1.0 documentation. Release-specific fixtures cover 12.2.0 mindmap branch/depth coloring; its other new syntax and layout changes still need qualification. The [Mermaid roadmap](../TODO.md#mermaid) records additional grammar, observed render comparisons, and qualification of newer reference versions.

## What support means

- **Native render path:** the parser produces a typed model and can create a CFX artifact for a supported subset.
- **Retained only:** source or metadata survives, but a requested feature does not affect visible output.
- **Approximate mapping:** meaning is projected into a CFX chart/topology model with documented fidelity limits. Journey, timeline, Venn and C4 report `CFXM009` while producing artifacts.
- **Diagnostic-only family:** the header is recognized and source is retained, but no artifact is produced.
- **Unknown family:** the header is not recognized and parsing returns an error.

Thirty families have native render paths. ZenUML, Agentflow and Railroad are diagnostic-only: their headers are recognized and source is retained without an artifact. Native rendering uses CFX scenes without Mermaid's browser runtime or reference-layout guarantee. Each native row still has open grammar, configuration or fidelity work; none of these counts establishes complete Mermaid compatibility. Existing smoke/artifact tests are evidence for their tested cases, not a claim that every upstream example passes.

## Recognized But Not Renderable Yet

These families are detected and returned as `MermaidDocument` with raw body statements in `RawStatements`, plus a warning diagnostic. They should not emit a visual artifact until a semantic model and deliberate ChartForgeX mapping exist.

| Family | Header | Current state | Best next target | Notes |
| --- | --- | --- | --- | --- |
| ZenUML | `zenuml` | Recognized, raw statements retained, warning diagnostic | Sequence-like artifact after grammar evaluation | Keep separate from Mermaid sequence until semantic differences are understood. |
| Agentflow | `agentflow-beta` | Recognized, raw source retained, `CFXM002`, no artifact | Typed workflows over reusable topology contracts | Semantic parsing and native rendering remain open. |
| Railroad | `railroad-beta`, `railroad-ebnf-beta`, `railroad-abnf-beta`, `railroad-peg-beta` | Recognized, raw source retained, `CFXM002`, no artifact | Typed grammar model and reusable railroad geometry | Body grammar is not validated by recognition. |

Complete the semantic and artifact gates for [Agentflow](https://mermaid.js.org/syntax/agentflow.html) and the [Railroad dialects](https://github.com/mermaid-js/mermaid/blob/mermaid%4012.1.0/packages/mermaid/src/docs/syntax/railroad.md). Treat workflow instructions/models/connectors as inert diagram data, and reuse one product-neutral grammar model for the Railroad notations. ZenUML remains a separate grammar/license evaluation; translating it as ordinary Mermaid sequence syntax would discard meaning.

## Shared Owners

Native hierarchy options, authored identities, chart orientation and relationship styling use the shared chart owner. Retained series replace complete hierarchy or flow data through `ReplaceHierarchyItems` and `ReplaceFlowData`; the [API conventions](v2/api-conventions.md) document configuration and identity rules. Bounded source configuration and located class/state/ER diagnostics belong to the Mermaid parser. Extend these owners when completing language mappings.

Remaining shared-owner work and its qualification belong in the [Mermaid roadmap](../TODO.md#mermaid).

## Completion Order

The implementation checklist lives in [TODO.md](../TODO.md#mermaid):

1. Establish versioned feature/semantic evidence and truthful diagnostics, including missing-family recognition.
2. Complete shared configuration, labels, styling, policy and layout owners.
3. Close core flowchart/sequence/class/state/ER/requirement semantics.
4. Qualify chart/calendar fidelity through the implemented shared native owners.
5. Complete specialized diagrams and implement missing language families against the same shared owners.
6. Qualify host delivery, visible exports, frameworks/AOT and package consumers; settle merge/release gates separately.

A family closes only when its documented syntax, semantics, diagnostics, visible scene, SVG/PNG exports and fence/consumer contracts pass. Retaining raw text or accepting one fixture is insufficient.
