# Mermaid Support Matrix

This matrix is the working contract for ChartForgeX Mermaid support. A family is complete only when it has source-preserving parsing, typed semantic models where rendering is implemented, diagnostics for unsupported syntax, deterministic SVG and PNG output where renderable, Markdown fence coverage, Mermaid.js conformance fixtures, and smoke tests that prove the public artifact contract.

The current semantic reference is **Mermaid.js 12.1.0**. The [test-time harness](../tests/mermaid-conformance/package.json) also pins 10.9.8 and 11.17.2; [per-fixture compatibility metadata](../tests/mermaid-conformance/compatibility.json) records syntax outcomes and explicit older semantic differences. These tested examples do not establish full compatibility with every release or syntax form in those majors. This inventory was checked against `main` at `09065c59` and upstream 12.1.0 documentation on 10 October 2026. Open candidates are listed separately below; their APIs and proof must be rechecked after merge.

## What support means

- **Native render path:** the parser produces a typed model and can create a CFX artifact for a supported subset.
- **Retained only:** source or metadata survives, but a requested feature does not affect visible output.
- **Approximate mapping:** meaning is projected into a CFX chart/topology model with documented fidelity limits.
- **Diagnostic-only family:** the header is recognized and source is retained, but no artifact is produced.
- **Unknown family:** the header is not recognized and parsing returns an error.

Thirty families have native render paths. ZenUML, Agentflow and Railroad are diagnostic-only: their headers are recognized and source is retained without an artifact. Each native row still has open grammar, configuration or fidelity work; none of these counts establishes complete Mermaid compatibility. Existing smoke/artifact tests are evidence for their tested cases, not a claim that every upstream example passes.

## Recognized But Not Renderable Yet

These families are detected and returned as `MermaidDocument` with raw body statements in `RawStatements`, plus a warning diagnostic. They should not emit a visual artifact until a semantic model and deliberate ChartForgeX mapping exist.

| Family | Header | Current state | Best next target | Notes |
| --- | --- | --- | --- | --- |
| ZenUML | `zenuml` | Recognized, raw statements retained, warning diagnostic | Sequence-like artifact after grammar evaluation | Keep separate from Mermaid sequence until semantic differences are understood. |
| Agentflow | `agentflow-beta` | Recognized, raw source retained, `CFXM002`, no artifact | Typed workflows over reusable topology contracts | Semantic parsing and native rendering remain open. |
| Railroad | `railroad-beta`, `railroad-ebnf-beta`, `railroad-abnf-beta`, `railroad-peg-beta` | Recognized, raw source retained, `CFXM002`, no artifact | Typed grammar model and reusable railroad geometry | Body grammar is not validated by recognition. |

Complete the semantic and artifact gates for [Agentflow](https://mermaid.js.org/syntax/agentflow.html) and the [Railroad dialects](https://github.com/mermaid-js/mermaid/blob/mermaid%4012.1.0/packages/mermaid/src/docs/syntax/railroad.md). Treat workflow instructions/models/connectors as inert diagram data, and reuse one product-neutral grammar model for the Railroad notations. ZenUML remains a separate grammar/license evaluation; translating it as ordinary Mermaid sequence syntax would discard meaning.

| Contract | Confirmed current state | Required completion |
| --- | --- | --- |
| Version coverage | Isolated reference lanes pin 10.9.8, 11.17.2 and 12.1.0. | Conformance depth | Representative `.mmd` sources in `tests/mermaid-conformance/fixtures`. | Result fidelity | Render results carry parser diagnostics. Guarded class/state/ER statements retain original spans with `CFXM007`; invalid directions and unmatched state/ER boundaries report `CFXM008`. Some accepted features remain metadata or flat-layout approximations. | Extend classification across the remaining grammar and compact statements; distinguish unsupported, retained, approximate and exact native mappings consistently. |
| Configuration and themes | Bounded YAML scalar mappings and legacy init/initialize declarations retain typed settings and original locations. Other settings have stable diagnostics. | Broader YAML forms, coherent host/source policy across families, remaining theme-variable and family-option mapping. |
| Mermaid 12 appearance | CFX uses its own deterministic prepared scene. It does not execute upstream ELK or reproduce the new default browser appearance. | Describe syntax/semantic compatibility separately from `layout`, `look`, theme and pixel fidelity. Handle legacy `defaultRenderer` and upstream layout aliases deliberately. |
| Labels and authored styling | Several parsers retain Markdown/icon/style data; visible application differs by family. Flowchart metadata shape aliases cover a subset of the upstream catalog. | Shared safe rich-text, shape and style mappings; explicit HTML/math/icon fallbacks, source-order/default-class semantics and SVG/PNG geometry proof. |
| Graph layout and notation | Shared topology provides native markers, groups and routing, but family-specific configuration and composite behavior remain incomplete. | Qualify nesting, local directions, group endpoints, ports, loops, parallel edges, obstacle/label routing and the actual class/state/ER/architecture notation. |
| Host policy and safety | Static output is script-free by default and existing topology/artwork safety contracts are reusable. `MermaidRenderOptions` is a per-family option container, without a Mermaid-wide family/style/resource policy. | Coherent diagram/style/link/asset policy and bounded source/model/output limits over existing safety owners; malformed/adversarial source and embedded SVG proof. | Delivery | Native artifact, fence, serialization and AOT tests exist, and the quality workflow covers Windows/Linux/macOS. This audit inspects source; it does not rerun those gates or verify published packages. | Qualify each completed tranche through direct APIs, fences, serialization, actual SVG/PNG views, representative hosts, supported frameworks/AOT and isolated package consumers. ## Completion Order

The implementation checklist lives in [TODO.md](../TODO.md#mermaid):

1. Establish versioned feature/semantic evidence and truthful diagnostics, including missing-family recognition.
2. Complete shared configuration, labels, styling, policy and layout owners.
3. Close core flowchart/sequence/class/state/ER/requirement semantics.
4. Qualify chart/calendar fidelity using existing owner candidates.
5. Complete specialized diagrams and implement missing language families against the same shared owners.
6. Qualify host delivery, visible exports, frameworks/AOT and package consumers; settle merge/release gates separately.

A family closes only when its documented syntax, semantics, diagnostics, visible scene, SVG/PNG exports and fence/consumer contracts pass. Retaining raw text or accepting one fixture is insufficient.
